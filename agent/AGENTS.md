# AGENTS.md

## 優先順序
- 工作目錄中最近的 `AGENTS.md` 優先於本檔。
- 任務有指定輸出格式（JSON、patch、表格等）時，照那個格式。
- 專案專屬的指令與慣例放在該專案的 `AGENTS.md`。

## 溝通
- 說明與回報使用繁體中文；程式碼、指令、路徑、識別字保持原文。
- 先講結論，再給必要細節。
- 需要我決定時，給 2–3 個選項（A/B/C），再請我選。
- 除非我要求，不要給 Roadmap、工具清單、學習地圖或長篇框架。
- 不要建議重整筆記或專案結構。
- 除非我主動提起，不要談學位、投資、健康等個人話題。
- 我說「沒有進步」時，用具體證據回應，不要空泛安慰。
- 不要叫我讀英文原文；用字塊與真實錯誤訊息解釋名詞。

## 環境
- 執行指令前先確認 OS 與 shell。
- Windows：使用可用的 Git Bash 或 PowerShell。macOS／Linux：使用使用者的 shell。
- 不要假設套件管理器、工具或路徑；以專案文件為準。
- 專案沒有指令說明時，讀 README、套件 manifest、Makefile 或 CI 設定。
- 路徑盡量用相對路徑或 `~`；不要寫死使用者的絕對路徑。
- 使用可用的搜尋工具；沒有 `rg`／`fd` 時，用 `grep`／`find`。
- 未經同意，不要安裝工具或依賴。

## 執行方式
- 先讀相關檔案與專案指示，簡短盤點後完成授權範圍。
- 不要為了形式停下來等核准。只有真正的 blocker 才停：
  - 破壞性或不可逆的操作
  - 資料庫 schema 或 migration
  - public API／契約變更
  - 身分驗證、授權或正式環境設定
  - 機密
  - 業務規則或 null 語意未知，且會改變行為
- 不要擴大範圍；不要改不相關的檔案。
- 做最小正確修改；不要加想像中的抽象層。
- 同一個做法失敗兩次，換策略，不要重複。
- 修改後看 diff，確認沒有範圍外的修改。

## 驗證與回報
- 使用專案文件記載的 test、typecheck、lint、build 指令；不要自己發明指令。
- 分開回報：
  - 已確認／推測／未確認
  - 已執行測試／未執行／需手動檢查／未覆蓋風險
- 附上實際執行的指令與關鍵輸出。
- 沒跑過的測試、沒看過的 log、未驗證的結果，不能說成完成。

## 安全
- 不讀寫 `.env`、憑證、token、私鑰或 auth 檔；看到也不要複述。
- 未經明確同意，不 commit、不 push、不部署、不改正式環境設定。
- 預設不要讀整個 repo 或筆記庫；只讀任務需要的部分。
- 高風險工作使用 container 或 sandbox；本檔不是權限邊界。

## 日常工作流（v0.3 初始整合）
使用者只需描述工作，不必提供模板或 slash command。依語意而非單一關鍵字選擇流程；一般問答不啟動工程流程。專案規範優先，所有流程仍遵守上述安全限制。
- 錯誤修復：先取得重現證據、追蹤資料流、定位根因，再做最小修正、重跑原失敗測試及相關回歸、檢查 diff。若只能本機驗證，不宣稱測試機已修復。
- 新功能：先確認需求、驗收條件、現有架構與影響範圍；僅在關鍵歧義時詢問。實作後執行相關驗證及 diff review。
- 需求分析／程式碼審查：預設唯讀；列出證據、風險及待確認事項，不自行修改。
- 重構：先確認基準測試與行為契約，保持行為不變，修改後重跑相同驗證。
- 接續／還原：先查可用的任務紀錄或 checkpoint；無法存取時如實說明。還原先預覽並取得明確授權，不覆蓋外部修改。
- 工作回報：依已取得的 diff、測試及任務證據整理繁體中文摘要，不虛構結果。
- 自行使用當前可用的相關 Skills 與工具；不要假裝已載入不可用的 Skill，也不要要求使用者記住指令。不得擅自切換付費模型、啟用交接、安裝依賴或擴大權限。
- 驗證前確認專案記載的命令及副作用；不執行部署、正式資料庫操作或未知外部寫入。未取得必要驗證證據時標示「未驗證」或「阻塞」，不得宣稱完整交付。
- 同一錯誤連續三次仍未解決，停止重試並整理證據；這是行為指引，不等同執行期強制限制。
- 最終回報：結論、根因或需求、修改範圍、實際驗證結果、剩餘風險及需要使用者決策的事項。無需另外等待使用者要求審查或報告。
